# Python backend self-test fixture

The Python backend validates **itself**: this directory is a small,
hand-written codebase plus the ground truth for how every call and import in
it *should* be resolved. `main.py test-backend --backend python` runs the
backend's own translator over the fixture, builds the call graph, and checks
the result against the truth. No LLM, no network — the checks are pure
static-vs-runtime comparison.

```
main.py test-backend --backend python     # 0 = all green, 1 = red, 2 = no fixture
```

## Two-track design

A fixture module must be *executable* for the runtime to reveal the truth,
but a module that is deliberately broken (a call with no target, an
unresolvable import) **cannot** be imported without raising. So the fixture is
split into two tracks:

1. **The executable core** (top-level and `pkg/`, `deep/`). These modules are
   import-clean: `generate_truth.py` imports them in a fixed order, calls each
   module's zero-arg `run()`, and the `@probe.traced` wrappers record the
   runtime truth (which function actually ran, from which site). This is the
   *self-reporting* half — the truth is generated by the language itself, not
   by a human annotator, so it cannot drift from what CPython does.

2. **The inert traps** (`inert/`, no `__init__.py`, **never imported**). These
   hold the deliberately-broken call sites and imports — dynamic receivers,
   unknown globals, ambiguous bindings, a missing relative sibling, a
   single-candidate inference. Because they are never executed, their broken
   imports never raise, and their expected outcomes are declared with `#`
   markers instead of runtime truth.

Everything is standard-library only. `inert/` has **no** `__init__.py` so it
is a namespace that nothing imports.

## How the truth is produced

`generate_truth.py` (run with the fixture root on `sys.path[0]`) emits JSON:

- **`calls`** — one entry per distinct resolvable call site:
  `{site:{file,line}, callee, origin:{file,line,name}}`. `origin` is where the
  callee is **defined** (from `func.__file__` + the `def` line — see
  `_def_line`, which skips decorators because CPython reports the first
  decorator line for a decorated function); `site` is where it was called.
- **`imports`** — one entry per top-level import of an imported module:
  `{file,line,bound,module_file}`, where `module_file` is the fixture-relative
  path of the imported module, or `null` for stdlib (an unresolved import by
  design).

The checker (`kodama_docs/testing.py`) then verifies, per site:

- every `calls` entry has a CALLS edge at `site` pointing to the node at
  `origin`, classified `resolved` (or `inferred`, which still counts as a
  successful resolution);
- every `imports` entry with a `module_file` has a resolved IMPORTS edge to it,
  and one with `null` is reported as an unresolved import;
- every `# expect:` marker in the inert traps matches the graph's diagnostic.

When the truth also carries **`modules`** meta (emitted by
`generate_truth.py`'s `_module_meta`, derived from the stdlib `ast` module —
independent of the backend's own tree-sitter walk), three more field-level
checks run against the extractor's records:

- **import-soundness** — per (file, line), the number of import records the
  extractor produced equals the number the runtime actually bound. A phantom
  `from m import n` (an extra record for `m`) shows up as
  `extracted=N runtime=M <-- phantom/missing`.
- **function meta** — for every AST-derived function, the extractor's record
  must agree on: `params` (order and names), `vararg`, `qualified` (full
  dotted name), and — when a developer comment is glued above the definition —
  a truthy `developer_comment`. Functions are keyed by **(name, line)** so
  recurring names like `__init__` across a hierarchy do not collide.
- **file vars** — every module-level variable the AST sees must be present in
  `file_vars`, and **no class attribute may leak in** (a leaked class attr is
  a failure).

These three checks are the "completeness + soundness + field" layer: they make
the previously-silent phantom import and every field-level parser bug visible.
The fixture modules `metalib.py` (a resolvable default-arg target) and
`meta_probe.py` (splat, vararg-guard, default-arg call, class attr,
file var, glued comments — plain and decorated) exercise each one, so any
regression re-fails a named check.

## Marker grammar (inert traps only)

A `#` comment **on the same line** declares the expected outcome:

| marker | meaning |
|--------|---------|
| `# expect: resolved <file>::<name>` | must link to that function |
| `# expect: inferred <file>::<name>` | allowed to be a single-candidate inference, but **labeled** inferred (never presented as verified) |
| `# expect: external <label> [...]` | recorded in `external_calls` under that label (one or more labels) |
| `# expect: ambiguous` | **no edge**; both candidates recorded in `ambiguous_calls` |
| `# expect: builtin <label>` | classified builtin |
| `# expect: import <file>` | resolved IMPORTS edge to that file |
| `# expect: import-unresolved` | the import is reported as unresolved |

The hard rule the whole fixture encodes: **failures are always visible.** A
dynamic receiver becomes `?.method` / `?` in `external_calls`, an ambiguous
binding becomes a diagnostic with its candidates, an unresolvable import
becomes an `unresolved` — nothing is silently dropped.

## Invariants the fixture pins down

- **Scope beats scan order.** `nest.py`: a nested `inner` shadows the
  module-level one only inside the enclosing function. `redef.py`: the *later*
  module-level definition is the live one.
- **Dotted module paths resolve.** `deep_user.py`:
  `deep.pack.mod.launch(...)` → `deep/pack/mod.py::launch`, and
  `import deep.pack` → `deep/pack/__init__.py` (package-root form).
- **Relative imports resolve to the sibling.** `pkg/a.py`, `pkg/c.py`,
  `pkg/sub/leaf.py` all land on `pkg/b.py::helper`; a missing sibling
  (`inert/badrel_user.py`) is an unresolved import and its call is external.
- **Ambiguity is never guessed.** `inert/amb_user.py`: the same name bound to
  two modules produces no edge plus a two-candidate diagnostic.
- **Inference is labeled.** `inert/unbound_user.py`: a unique project name may
  be inferred, but only marked `inferred`.
- **Case sensitivity, CRLF, BOM** (`case_user.py`, `crlf.py`, `bom.py`) and
  **stdlib shadowing** (`random.py` shadows the stdlib `random`; the fixture
  puts its own root on `sys.path[0]`, so the *fixture* module is the correct
  ground truth).
- **Field-level correctness** (`meta_probe.py`, `metalib.py`): the extractor
  must agree with the `ast`-derived oracle on parameters (order + names),
  `vararg`, the qualified name (`Widget.norm`, not `norm`), the developer
  comment glued above the first decorator line, a single record for a
  re-assigned file var, *no* leak of a class attr into `file_vars`, recognition
  of `*args`/`**kwargs`, and that a `*` in a default (`1024*1024`) is not a
  vararg. A call in a default-arg expression
  (`def norm(self, scale=make_default())`) must be extracted.

## Adding a case

- A **resolvable** site: add a module to the executable core, wrap the callee
  with `@probe.traced`, call it from a `run()`, and (if it is a new module)
  list it in `MODULES` in `generate_truth.py`. The truth appears automatically.
- A **deliberately unresolvable / conservative** site: add it under `inert/`
  and annotate with a `# expect:` marker.
- Keep `inert/` free of an `__init__.py`, and keep every inert module
  import-safe (it must never be executed).
