# Rendering

The last stage turns graph + prose into the files you read. It is pure and deterministic: same records, same graph, same settings → byte-identical markdown.

## Output layout

```
<output_dir>/
  index.md                 # one page: manual section + file table + analysis summary
  files/<relpath>.md       # one page per source file
  meta/                    # only when project.copy_meta is set
    graph.json  symbols.json  diagnostics.json
  manual/                  # only when project.manual_doc is set
    ...                    # your hand-written pages + non-md assets, copied as-is
```

## The file page

`render_file_md()` in `kodama_docs/markdown.py` lays each page out in a fixed order:

1. `# <relpath>` — the file path as the title.
2. **Summary** — the file's `summary` prose (`_No summary generated._` if none).
3. **Functions** — an index table: name (linked to the anchor below), line, parameter count, and a one-line description.
4. One `### name` section per function, in source order:
   - location (`*relpath:L–E*`);
   - the developer comment as a blockquote (when present);
   - **Description** (or an italic placeholder for `--no-llm` runs);
   - **Parameters** table — names always come from the *static* extraction; the LLM only adds descriptions, and prose arguments not in the signature are appended at the end;
   - **Outputs**, **Side effects**, **References**, **Uncertainties** — each block only appears when it has content;
   - the function's source in a fenced code block;
   - a **Callers** list when the graph says other functions call this one.
5. **Classes** table (only if the backend recorded classes); **File-level variables** table; a per-file **Unresolved references** note when this file has any.
6. Footer: *"Generated by kodama-docs. Prose produced by an LLM; structure and links generated deterministically."*

Every cross-page link is computed from the graph (`ref_line`): links go to the target file's page and the target's in-page anchor (`#fn-<name>-<line>`).

## When prose is missing

Nothing breaks. A function without prose gets an italic placeholder instead of a Description; a file without a summary gets `_No summary generated._`; a function with no LLM references falls back to `static_references()` — the same deterministic list built from the graph (call targets, marked "(inferred)" where the resolver inferred them, and orange-highlighted when they resolved to nothing in the project). This is why a `--no-llm` run still produces a fully navigable documentation set.

## The index page

`render_index()` writes `index.md`:

- **Manual documentation** — a nested bullet list of a configured `project.manual_doc` folder (this manual is one; see [Documenting kodama-docs Itself](../05%20-%20Examples/02%20-%20Documenting%20kodama-docs%20Itself.md)): one plain bullet per folder (nested one level per folder), one link per page;
- a table of all documented files with line / function / variable counts;
- an **Analysis summary** — per-file analysis status (ok / failed / binary with reasons) and the resolution counts: how many call references and imports resolved, how many calls were recorded as external, inferred, or ambiguous. Failures and gaps are *visible in the docs*, not only on the console.

## Where it goes from there

The rendered markdown is static; `kodama_docs/web.py` (the `--serve` server) only presents it, plus the `/graph` interactive view backed by `meta/graph.json`. Serving details are in [Serving](../01%20-%20Getting%20Started/04%20-%20Serving.md).
