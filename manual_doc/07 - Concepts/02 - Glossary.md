# Glossary

Terms used throughout the manual, in the sense the code uses them.

| Term | Meaning |
| --- | --- |
| **Backend** | A language extractor. A backend claims a source extension, provides `extract(source, relpath)`, and (for some languages) a builtin-name set. Backends register into a central registry and report `ready` / `unavailable` / `conflict` / `invalid`. See [Backends](../03%20-%20Components/01%20-%20Backends.md). |
| **Built-in (builtin)** | A name from the caller language's standard set (`print`, `pairs`, `os.path`, …). Calls to these are marked `builtin` — recognized, but not a project symbol, so they render as orange with no link. |
| **Candidate** | One of several project definitions matching an ambiguous name. Ambiguous call sites record their `candidates` instead of linking to any one. |
| **Chunk-and-merge** | For functions longer than `documentation.max_function_lines`, the body is split into chunks, each summarized separately, and the summaries are merged into a single description. See [Chunk and Merge](../02%20-%20How%20It%20Works/06%20-%20Chunk%20and%20Merge.md). |
| **Dirty** | A file whose md5 changed since the last written `.doc_cache`. Its cached records are deleted and it is re-run. |
| **Edge** | A directed relationship in the [Symbols and Graph](01%20-%20Symbols%20and%20Graph.md): `CONTAINS`, `CALLS`, `IMPORTS`, or `READS`. |
| **External** | A reference that is outside the documented project (third-party or system). Kept as a synthetic node so the docs can say "unresolved" rather than guess. |
| **Fingerprint** | A hash used as a cache key. Record fingerprints fold in the symbol's source, its callers/callees, shaping settings, and the model; the scan fingerprint and the `.doc_cache` md5s are separate, coarser keys. |
| **Inferred** | A reference to a name defined exactly once project-wide but not import-bound. Kept and shown, but labeled `(inferred)` so the docs stay honest that it is a guess. |
| **Node** | A symbol or file in the [Symbols and Graph](01%20-%20Symbols%20and%20Graph.md). Kinds: `file`, `function`, `variable`, `class`, `module`, `builtin`, `external`. |
| **Placeholder / stub** | The `--no-llm` prose ("No summary generated (`--no-llm`)") written when the model is skipped. Records marked `stubbed` are treated as cache misses by a later full run. |
| **Prose** | The human-readable description text generated by the LLM for a function, variable, or file summary — as opposed to the deterministic structure (links, tables, code) the pipeline always produces. |
| **Record** | One generated LLM result stored under `data/{functions,variables,summaries,chunks}/`, with its `fingerprint` and optional `stubbed` flag. |
| **Resolution** | Deciding, for a call/import, which definition it points to. Outcomes: `resolved`, `inferred`, `builtin`, `external`, or **ambiguous** (no edge). See [Symbols and Graph](01%20-%20Symbols%20and%20Graph.md). |
| **Schema** | The per-kind JSON shape the LLM must return (and the validator enforces). Embedded verbatim in the prompt, so the model and the validator can't disagree. See [Prompts](../04%20-%20Reference/03%20-%20Prompts.md). |
| **Skip** | Reusing a cached record for a symbol whose fingerprint matches, so no network call is made. Reported as `skipped=N` in the phase log. |
| **Stale** | A file present in the `.doc_cache` but no longer in the scan (removed since). Its cached records are deleted. |
| **Status (CALLS edge)** | One of `resolved` / `inferred` / `builtin` / `external`. See [Symbols and Graph](01%20-%20Symbols%20and%20Graph.md). |
| **Stub / `--no-llm`** | Run the full pipeline without any LLM calls: real structure and links, placeholder prose. |
| **Symbol** | A function, variable, or class extracted from a source file by a backend. |
| **TUI** | The Rich terminal panel (per-agent rows, per-kind totals, log tail) shown during the LLM phase when stdout is a TTY. |
| **Work item / job** | One LLM task (a function, variable, summary, or chunk) in the phase's queue. |

## Phases, in order

1. **Scan + extract** — walk the tree, run the backends, cache `symbols.json`.
2. **Graph** — build the resolution graph and diagnostics.
3. **LLM phase** — generate (or reuse) prose per symbol, respecting the record cache.
4. **Render** — emit `index.md`, per-file pages, and (optionally) the manual and meta copies.
