CLI

main.py remains the implementation entry point. pyproject.toml also installs a kodama-docs console script (same CLI), so from a checkout either of these works:

Source 
python main.py --config settings.yaml
kodama-docs --config settings.yaml

All flags live on one flat parser; the two subcommands are init and test-backend.

All flags

Flag Default Meaning
init—write a starter settings.yaml and prompts/ into the current directory. Refuses to overwrite without --force.
--forceoffinit only: overwrite an existing settings.yaml and prompt files.
--config PATH—config file (.yaml or .yml), required for pipeline/--serve/--purge/--regenerate; a relative path resolves against the config's own directory for sibling keys. Bare kodama-docs prints help instead of guessing settings.yaml.
--no-llmoffoffline mode: no model calls, stub prose, no per-task delays. Fast first pass / structure check. See Caching.
--freshoffignore the per-file analysis cache (<data_dir>/symbols.json) and re-extract every file. Records and docs are still reused.
--purgeoffdelete the output dir, data dir, and record caches and exit — no run happens.
--regenerateoffsame deletes as --purge, then run from scratch. (The two are mutually exclusive by construction — one runs, one doesn't.)
--list-backends—print the backend registry (name, version, api, extension, status, issues) and exit.
--install URL—git-clone a backend repo into backends/<name>/ and pip-install its declared python deps; exit.
--remove NAME—delete one installed backend; exit.
--serveoffstart the web server on web/web_settings.yaml (default http://127.0.0.1:8123) and exit.
--staticoffcombine with a normal run: afterwards also build a self-contained static site into <output_dir>/site (open site/index.html directly, or host the folder, e.g. GitHub Pages — no server needed). See Web Server.
test-backend --backend NAME—run the named backend's self-test harness and exit; --backend is required.

Precedence

The CLI is evaluated in this order; the first matching mode wins and exits:

  1. --list-backends / --install / --remove — printed, executed, done.
  2. init — write starter settings.yaml + prompts/ and exit.
  3. test-backend — runs the harness with the named backend (status must be ready); exit code 0 on a full pass, non-zero on any failed check.
  4. --purge / --regenerate — delete output_dir, data_dir, and the record caches (--regenerate continues, --purge stops).
  5. --serve — web server on the config's output dir (or docs_dir).
  6. the pipeline run — scan → analyze → graph → LLM phase → render → (with --static) the static site build.

Exit codes

Code Meaning
0success (including --no-llm runs, purges, clean backend lists).
1at least one LLM task failed after retries — docs were still written for everything that succeeded; the failing prose is a visible placeholder, not silent.
non-zeroerrors (SystemExit messages: config not found, no ready backend for a language, test-backend without --backend, self-test failures).

Typical invocations

Source 
# scaffold a new project (settings.yaml + prompts/)
kodama-docs init

# inspect the project, no model (console script works too)
python main.py --config settings.yaml --no-llm
kodama-docs --config settings.yaml --no-llm

# full run (uses .env + settings.yaml)
python main.py --config settings.yaml

# full run from a clean slate (drops docs, records, caches)
python main.py --config settings.yaml --regenerate

# serve the last run
python main.py --config settings.yaml --serve

# build a server-free static site into <output_dir>/site
python main.py --config settings.yaml --static

# bare invocation is a safe help request; it never guesses a config
python main.py
kodama-docs

# what backends are here, and what is missing? (no config needed)
python main.py --list-backends

# verify the Python backend (CI-friendly, no config needed)
python main.py test-backend --backend python
