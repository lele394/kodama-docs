kodama-docs

kodama-docs reads a source codebase and turns it into browsable, cross-linked documentation. The exact, structural parts — which files exist, what each function is, which symbols call or import which — are computed deterministically from the code. A local or remote LLM then writes only the human prose (summaries and explanations) around that fixed structure. The result is a static site: an index.md, one page per source file, and this manual.

What this manual is

The project README (in the repository root) is a quick overview. This manual is the deeper, sectioned reference: how each part of the tool works, every configuration key, each language backend, and the things that go wrong and how to fix them.

This "Manual" group is section 0 of every build — the one place where hand-written content sits at the top of the sidebar, above the generated docs. No LLM is involved in this content.

How it is organized

  • 01 - Getting Started — install, your first run, configuration, serving.
  • 02 - How It Works — the pipeline, determinism, the graph, chunk-and-merge, caching.
  • 03 - Components — backends, the Lua, Python and C/C++/CUDA backends, the LLM client, the web server, the CLI.
  • 04 - Reference — every config key, the output and data formats, the prompts.
  • 05 - Examples — end-to-end walkthroughs, including kodama-docs documenting itself.
  • 06 - Troubleshooting — LLM, parsing, and performance problems.
  • 07 - Concepts — the symbol/graph model and a glossary.
  • 08 - Contributing — how to add a language and how the code is organized.
  • 09 - FAQ — common questions.
